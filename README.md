# 🎄 Бот для дропшиперів — ялинки та новорічний декор

Всі файли лежать пласко (без папок) — завантажуються на GitHub простим перетягуванням.

## Запуск
1. Створіть бота у @BotFather, збережіть токен
2. `python setup_np.py ВАШ_КЛЮЧ_НП "Ваше місто"` — видасть 6 рядків для змінних
3. Google Таблиця замовлень: Розширення → Apps Script → вставте `orders_webhook.gs` → Деплой як веб-додаток (доступ: усі) → URL = SHEET_WEBHOOK_URL; у Налаштуваннях проєкту → Властивості скрипту додайте SHEETS_API_SECRET (довгий випадковий рядок)
4. Railway: Deploy from GitHub repo → Variables:
   - BOT_TOKEN, ADMIN_IDS
   - NP_API_KEY, NP_SENDER_REF, NP_SENDER_CONTACT_REF, NP_SENDER_CITY_REF, NP_SENDER_WAREHOUSE_REF, NP_SENDER_PHONE
   - SHEET_WEBHOOK_URL, SHEETS_API_SECRET (те саме значення, що у Властивостях скрипту)
   - опційно: PRICE_TIER (drop1/drop2/drop3), NP_PAYER_TYPE (Recipient/Sender), ADMIN_CHAT_ID, WEBLIUM_SECRET

## Команди адміна
/users — список дропшиперів, /block ID — закрити доступ, /reload — оновити ціни з прайсу, /id — показати ID чату

## Тариф дропшипера
В аркуші «Дропшипери» є колонка **«Тариф»**: `drop1` / `drop2` / `drop3` (можна писати «Дроп 2»).
Порожньо — діє загальний `PRICE_TIER` із змінних. Бот колонку лише читає й не затирає,
коли оновлює рядок дропшипера.

## Залишки дропшиперів
Аркуш «Залишки дропшиперів» ведеться руками, бот його лише читає. Колонка «Дроп-ціна» —
довідкова: ціну бот завжди бере з прайсу за тарифом. При старті бот звіряє артикули залишків
із каталогом і пише в лог ті, що не знайшлися (часта причина — вкладки прайсу немає
в `PRICELIST_TABS`, лікується `/reload` або `/gids`).

Артикули в прайсі подекуди набрані з кириличними літерами («Cr6сustom-220» з кириличною с).
Для пошуку бот зводить артикул до канонічного вигляду (`article_key.py`), але зберігає й друкує
в ТТН **оригінальний** рядок із прайсу.

## Резерв залишків і статуси Нової Пошти
Бот резервує товар у «Залишках дропшиперів» **до** створення ТТН: не вистачає — замовлення не
оформлюється й накладна не створюється. Колонки: G «Зарезервовано», H «Отримано», J «Оновлено».
Колонку I «Доступно» (формула `=F-G-H`) не пише ніхто — перевірити формули можна функцією
`checkAvailableFormulas()` у редакторі Apps Script.

Раз на `TTN_POLL_SECONDS` (типово година, `0` — вимкнути) бот перепитує статуси ТТН у НП і реагує
**на зміну** статусу, не на сам статус:
* «отримано» → резерв стає видачею (G → H);
* «відмова/повернення» → лише повідомлення адміну, резерв лишається (рішення за людиною);
* «видалено» (код 2) → резерв знімається одразу;
* «номер не знайдено» (код 3) → резерв НЕ знімається одразу: НП так відповідає й на щойно
  створену накладну. Перший раз — лише лист адміну, резерв стоїть. Знімаємо, тільки якщо код 3
  повторився на наступній перевірці І замовленню понад добу; у статус дописується
  «· резерв знято», щоб не зняти його вдруге.

## Дублювання замовлень у таблицю дропшипера
У Властивостях скрипту: `DROPSHIPPER_EXPORT_SHEETS_JSON` = `{"Telegram ID":"ID таблиці"}`.
Обліковий запис, під яким працює скрипт, має бути редактором тієї таблиці. Збій експорту
не зриває замовлення — воно однаково потрапляє в головну таблицю. Разово перенести старі
замовлення: функція `syncDropshipperOrdersFromAll()` у редакторі.
